# fortee-vote-navigator

[fortee](https://fortee.jp) のスタッフ投票ページ（CfP採点）を回しやすくする Chrome 拡張です。

数十〜百件規模のプロポーザルを上から読んでいくと、

- スクロールするうちに「自分がどこに何点を入れたのか」が分からなくなる
- 全体の分布が見えないので、点数の付けすぎ・偏りに後から気づけない
- 「あとで見直したい」と思ったものを覚えておけない

といったあたりが素の画面ではつらいので、そこだけを補います。採点そのものはページ側の機能をそのまま使います。

## 機能

| | |
| --- | --- |
| **サマリーバー** | 画面下部に固定。各スコアの件数と全体に対する割合（`3件 30%`）を常時表示します。 |
| **スコアチップ** | 各プロポーザルのタイトル横に現在のスコアを表示。本文が長くて採点ボタンが画面外にあっても、自分の点数が分かります。 |
| **フィルタ** | サマリーバーのバッジをクリックすると、そのスコアを付けたものだけを表示。`+1` だけを並べて `+2` / `0` に振り分け直す、といった調整に使います。複数選択可。 |
| **2種類のフラグ** | 「あとで見直す」印を左旗・右旗の2つ用意しています。ブラウザに保存され、リロードしても残ります。旗ごとにフィルタでき、両方選ぶと和集合になります。 |
| **操作テンプレート** | キー操作を2種類から選べます（後述）。初期値は「矢印キー」。バーのセレクトで切り替え、選択は保存されます。 |
| **採点したら次へ** | 採点すると次のプロポーザルへ自動で移動します。**初期状態では無効**で、バーのチェックで有効にします。フィルタ中は、フィルタ後の次へ飛びます。 |

### 2つのフラグについて

**意味づけは利用者に委ねています。** 拡張としては「左旗（赤）」「右旗（青）」という中立な2つの印を用意するだけです。「右がよかったかも、左がよくなかったかも」のように正負で使い分けてもいいですし、「気になる／確認したい」のような軸で使っても構いません。大事なのは2種類あることです。

## キーボード

### フラグ（両テンプレート共通）

| キー | 動作 |
| --- | --- |
| `z` / `x` | 左旗 / 右旗をトグル |
| `shift` + `z` / `x` | 次の左旗 / 右旗へジャンプ |

### テンプレート1: 矢印キー（初期値）

移動と採点を矢印キーに寄せ、右手だけで一周できるようにしたものです。

| キー | 動作 |
| --- | --- |
| `↑` / `↓` | 前 / 次のプロポーザルへ移動 |
| `←` / `→` | スコアを1段ずらす |
| `z` / `x` | フラグ |

`←` `→` の向きは**画面の採点ボタンの並び（`+2` `+1` `0` `-1` `-2`）に一致**します。つまり `←` が高得点方向です。初期値の `0` から `←` 一回で `+1`、二回で `+2`。

連打の途中経過で投票が飛ばないよう、**最後の入力から 350ms 待ってから確定**させます。確定前のスコアはチップに点線枠で表示されます。

このテンプレートでは矢印キーによるページスクロールが効かなくなります。長い概要を読むときはマウスホイールか `space` / `PageDown` を使ってください。`1`〜`5` の数字キーは fortee 側のものがそのまま残るので、直接指定したいときはそちらも使えます。

### テンプレート2: fortee 準拠

fortee 本来のキーをそのまま使い、フラグだけを足したものです。

| キー | 動作 | 担当 |
| --- | --- | --- |
| `j` / `k` | 上下に移動 | fortee |
| `1`〜`5` | `+2`〜`-2` を入力 | fortee |
| `shift` + `j` / `k` | 未投票へジャンプ | fortee |
| `z` / `x` | フラグ | 拡張 |

フィルタ中だけは `j` / `k` を拡張が引き取り、隠れているプロポーザルを飛ばして移動します。

## インストール

```bash
npm ci
npm run build
```

Chrome の `chrome://extensions` を開き、デベロッパーモードを有効にして「パッケージ化されていない拡張機能を読み込む」から `dist/` を選びます。

開発中は `npm run watch` で差分ビルドし、拡張機能ページの再読み込みボタンを押してください。

## 動作対象

`https://fortee.jp/*/organizer/proposals/vote/*` にのみ注入されます。イベントの slug（URL の先頭セグメント）ごとにフラグを保存するので、複数のイベントで併用できます。

権限は `storage` のみで、外部への通信は一切ありません。

## 実装メモ

ページ側の DOM 構造への依存は `src/page.ts` に閉じ込めています。2026-08 時点で確認した構造:

```
div.proposal4staffvote[.active]
  div.proposal
    div.length          … "CFPセッション(15分)"
    div.title > h2      … タイトル
    div.abstract
  div.scores
    button.btn.btn-primary            … 選択中のスコア
    button.btn.btn-outline-secondary  … 未選択（左から +2, +1, 0, -1, -2）
```

- **プロポーザルIDが DOM 上に存在しない**ため、フラグの識別子はタイトルのハッシュ（djb2）を使っています。並び替え（登録順／タイトル順）で位置が変わっても追従します。保存領域に CfP のタイトルそのものは残しません。
- `.active` はページ側が管理しているので、拡張からはクラスを直接触らず、**タイトルのクリック**でフォーカスを移しています。
- 採点ボタンは Vue 側で `$emit("vote")` を出しているため、矢印キーでの採点は**ボタンのクリック**として流し込んでいます（数字キーと同じ経路）。
- テンプレート2でページ側のキー操作を止められるのは、`document` の **capture フェーズ**で `stopPropagation()` しているからです。fortee 側のハンドラはそれより内側にいます。
- 採点の検知は `MutationObserver` で `.scores button` のクラス変化を見ています。「採点したら次へ」は、採点後 250ms 待ってもフォーカスが動いていなければ拡張側で進める方式にしており、将来ページ側が自動で進むようになっても二重に飛びません。

## テスト

```bash
npm test
```

jsdom 上に投票ページを模した DOM を組み立て、ビルド済みの content script を流し込んでサマリー集計・フィルタ・フラグ・自動移動を確認します。

> **注意**: 採択前のプロポーザル本文や各票の集計は公開情報ではありません。テストフィクスチャやスクリーンショットに実際の CfP を含めないでください（`test/fixture.mjs` はダミータイトルを生成します）。
